# Plan 01-03: Canonical theory taxonomy config and legacy label alias inventory

## Objective

Encode the Arbor taxonomy as a versioned project contract and inventory the legacy label aliases the pipeline must normalize before any supervised dataset is assembled.

<must_haves>
- The six canonical theory classes are defined in repo config with Arbor-consistent ordering and wording.
- Alias handling preserves both `label_original` and `label_canonica`.
- `RM` and `RC` resolve to canonical Type 2, while unresolved or blank labels are surfaced through review status fields.
</must_haves>

<tasks>
<task id="01-03-01">
<title>Encode the Arbor taxonomy as the canonical label contract</title>
<read_first>
- Article/Artículo_Arbor.pdf
- docs/alcance_cliente/decision_taxonomia_canonica.md
- .planning/phases/01-canonical-taxonomy-and-corpus-contracts/01-CONTEXT.md
- .planning/phases/01-canonical-taxonomy-and-corpus-contracts/01-RESEARCH.md
</read_first>
<action>
Create `configs/taxonomy.toml` with the six canonical Arbor class identifiers in fixed order and human-readable labels derived from the article. The config must make the project-level semantic truth explicit so later label harmonization does not depend on notebook shorthand or ad-hoc CSV conventions.
</action>
<acceptance_criteria>
- `configs/taxonomy.toml` contains exactly six canonical class identifiers
- the class list includes `tipo_1_realismo_fuerte` through `tipo_6_constructivismo_fuerte_relativismo`
- the order in the config matches the Arbor numbering from Type 1 to Type 6
</acceptance_criteria>
</task>

<task id="01-03-02">
<title>Implement alias mapping and canonical-label normalization helpers</title>
<read_first>
- configs/taxonomy.toml
- Seed/Seed.xlsx
- docs/alcance_cliente/decision_taxonomia_canonica.md
</read_first>
<action>
Implement taxonomy-loading and normalization helpers in `src/abstract_classifier/taxonomy.py`. The normalization result must preserve `label_original`, compute `label_canonica`, and emit `mapping_status`, `mapping_notes`, and `review_required`. Hard-code the approved alias policy that maps both `RM` and `RC` to canonical Type 2, and treat blank or structurally unresolved labels as review cases rather than silent positives.
</action>
<acceptance_criteria>
- normalization code returns or persists `label_original`, `label_canonica`, `mapping_status`, and `review_required`
- alias handling contains both `RM` and `RC` mapped to canonical Type 2
- blank labels produce a non-success mapping status
- `python -m pytest tests/test_taxonomy_contract.py -q` exits 0
</acceptance_criteria>
</task>

<task id="01-03-03">
<title>Expose a taxonomy inventory/report path for Phase 2 input</title>
<read_first>
- src/abstract_classifier/taxonomy.py
- src/abstract_classifier/commands/prepare.py
- .planning/phases/01-canonical-taxonomy-and-corpus-contracts/01-VALIDATION.md
</read_first>
<action>
Add a `prepare`-side workflow that can read legacy labels from the supervised sources and emit a taxonomy inventory report suitable for Phase 2. The report must separate direct mappings, approved aliases, and review-required cases so the next phase can assemble the gold set without re-inventing the label contract.
</action>
<acceptance_criteria>
- the prepare workflow can emit a taxonomy inventory artifact under `reports/`
- the inventory distinguishes direct mappings, alias mappings, and review-required rows
- the report references the canonical label identifiers defined in `configs/taxonomy.toml`
- `python -m pytest tests/test_taxonomy_contract.py -q` exits 0
</acceptance_criteria>
</task>
</tasks>
