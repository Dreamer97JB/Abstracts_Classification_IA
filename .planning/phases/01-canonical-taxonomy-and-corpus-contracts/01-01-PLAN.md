# Plan 01-01: Package skeleton, config surface, and CLI entrypoints

## Objective

Create the minimal package and command surface that turns this repo from notebook-first execution into script-first execution without breaking the current exploratory workflow.

<must_haves>
- The repo exposes named entrypoints for `audit`, `prepare`, `train`, `evaluate`, `predict`, and `analyze`.
- The package surface lives under `src/abstract_classifier/` and becomes the operational source of truth.
- The existing audit workflow is callable through the package entrypoint, not only through a standalone script.
</must_haves>

<tasks>
<task id="01-01-01">
<title>Create the package skeleton and command router</title>
<read_first>
- pyproject.toml
- README.md
- scripts/data_audit.py
- .planning/phases/01-canonical-taxonomy-and-corpus-contracts/01-CONTEXT.md
- .planning/phases/01-canonical-taxonomy-and-corpus-contracts/01-RESEARCH.md
</read_first>
<action>
Create `src/abstract_classifier/` with `__init__.py`, `cli.py`, and a `commands/` package. Implement an `argparse` command router with top-level commands named exactly `audit`, `prepare`, `train`, `evaluate`, `predict`, and `analyze`. Each command must resolve to an importable handler function even if some handlers are still placeholders that print a clear "not implemented yet" message and exit non-fatally.
</action>
<acceptance_criteria>
- `src/abstract_classifier/cli.py` contains subparsers named `audit`, `prepare`, `train`, `evaluate`, `predict`, and `analyze`
- `python -m abstract_classifier.cli --help` exits 0
- `python -m abstract_classifier.cli audit --help` exits 0
- `python -m abstract_classifier.cli prepare --help` exits 0
</acceptance_criteria>
</task>

<task id="01-01-02">
<title>Move the current audit logic behind the package surface</title>
<read_first>
- scripts/data_audit.py
- README.md
- src/abstract_classifier/cli.py
</read_first>
<action>
Extract or wrap the current audit implementation so the reusable logic lives under `src/abstract_classifier/commands/` and the legacy `scripts/data_audit.py` script becomes a thin compatibility entrypoint. Keep the current report behavior (`--output reports/data_audit.md`) intact, but make the package command the canonical execution path.
</action>
<acceptance_criteria>
- `scripts/data_audit.py` imports shared logic from `src/abstract_classifier/` or clearly delegates to the package implementation
- the shared audit module contains a callable function that returns or writes the markdown audit report
- running the audit through the package preserves the existing `reports/data_audit.md` output path behavior
</acceptance_criteria>
</task>
