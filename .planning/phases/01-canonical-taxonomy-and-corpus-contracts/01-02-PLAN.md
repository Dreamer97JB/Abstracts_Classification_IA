# Plan 01-02: Source manifests and overlap audit

## Objective

Define governed source manifests for all client datasets and implement the exact-match overlap audit that Phase 2 and later phases will trust.

<must_haves>
- Google, Scopus, Seed, and `Muestras` are represented as explicit source specs with lineage fields.
- The overlap audit uses only exact DOI or exact normalized title + same year rules for auto-merge candidates.
- Ambiguous matches are emitted as manual review rows rather than silently merged.
</must_haves>

<tasks>
<task id="01-02-01">
<title>Define source manifests and corpus roles</title>
<read_first>
- .planning/phases/01-canonical-taxonomy-and-corpus-contracts/01-CONTEXT.md
- .planning/phases/01-canonical-taxonomy-and-corpus-contracts/01-RESEARCH.md
- Database/Scopus_database.xlsx
- Seed/Seed.xlsx
- googleScholarPeriodAbs.xlsx
</read_first>
<action>
Create `configs/sources.toml` that declares four governed sources: Google corpus, Scopus base corpus, Seed gold workbook, and Scopus `Muestras`. Each source entry must include the exact file path, source dataset identifier, workbook sheet when applicable, declared role (`corpus`, `initial_gold`, or `aux_review`), and lineage fields needed to preserve provenance in downstream tables.
</action>
<acceptance_criteria>
- `configs/sources.toml` contains entries for Google, Scopus base, Seed, and `Muestras`
- the Seed entry is marked as `initial_gold`
- the `Muestras` entry is marked as `aux_review`
- each source entry contains explicit path and sheet metadata when the source is workbook-based
</acceptance_criteria>
</task>

<task id="01-02-02">
<title>Implement normalized source loading and overlap-key generation</title>
<read_first>
- configs/sources.toml
- src/abstract_classifier/cli.py
- .planning/phases/01-canonical-taxonomy-and-corpus-contracts/01-CONTEXT.md
</read_first>
<action>
Add source contract models plus ingestion helpers that read the governed sources and emit normalized rows with lineage columns including `source_dataset`, `source_sheet`, `doi_normalized`, `title_normalized`, and `year`. Implement overlap-key generation with exactly two auto-merge rules: `doi_normalized` equality, or `title_normalized` equality plus same `year`. Any other near match must be classified as `manual_review`, not merged.
</action>
<acceptance_criteria>
- normalized rows include `source_dataset`, `source_sheet`, `doi_normalized`, `title_normalized`, and `year`
- overlap logic contains a DOI equality path and a title+year equality path
- non-exact title matches do not produce an auto-merge outcome
- `python -m pytest tests/test_source_manifest_contract.py -q` exits 0
</acceptance_criteria>
</task>
