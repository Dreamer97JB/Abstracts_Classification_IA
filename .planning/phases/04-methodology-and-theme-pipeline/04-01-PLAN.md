# Plan 04-01: Implement methodology classification with optional evaluation

## Objective

Turn methodology into an operational, governed workflow that infers the agreed hierarchy from text evidence today and can emit a real evaluation bundle later when reviewed methodology labels are supplied.

<must_haves>
- Methodology output follows the exact hierarchy `NN`, `no_empirico`, `empirico -> cualitativo|cuantitativo`.
- Conflicting or insufficient evidence is flagged explicitly instead of forced.
- Evaluation artifacts are written only when reviewed methodology labels are available.
</must_haves>

<task id="04-01-01">
<title>Create a versioned methodology baseline config and heuristic classifier</title>
<read_first>
- .planning/phases/04-methodology-and-theme-pipeline/04-CONTEXT.md
- .planning/phases/04-methodology-and-theme-pipeline/04-RESEARCH.md
- configs/methodology.toml
- reports/phase2_methodology.csv
- src/abstract_classifier/methodology.py

<action>
Create `configs/methodology_baseline.toml` and a methodology pipeline module that loads the governed Phase 4 input rows, composes keyword-aware analysis text, matches config-driven cue vocabularies, and emits validated methodology assignments plus review reasons and evidence summaries. The classifier must support `NN`, `no_empirico`, and `empirico`, and only assign `cualitativo` or `cuantitativo` when empirical evidence is clear enough.
</action>
<acceptance_criteria>
- `configs/methodology_baseline.toml` exists and captures the default input artifact, text variant, review thresholds, and cue vocabularies
- heuristic methodology assignments pass through `validate_methodology_assignment`
- rows with no signal can resolve to `NN`
- rows with conflicting subtype cues are flagged for review instead of forced

</acceptance_criteria>
