# Plan 03-01: Implement canonical theory training and evaluation flow with artifact persistence

## Objective

Replace the placeholder theory training and evaluation commands with a reproducible, governed baseline workflow that consumes the Phase 2 gold split, persists run artifacts, and writes a full metrics bundle aligned to the canonical taxonomy.

<must_haves>
- Training and evaluation consume the Phase 2 gold and split artifacts directly.
- `train` and `evaluate` stop using the placeholder handler.
- Every run persists a deterministic manifest plus reviewable artifact files.
</must_haves>

<tasks>
<task id="03-01-01">
<title>Create a versioned baseline config and governed dataset loader</title>
<read_first>
- .planning/phases/03-baseline-theory-classifier/03-CONTEXT.md
- .planning/phases/03-baseline-theory-classifier/03-RESEARCH.md
- reports/phase2_gold_supervision.csv
- reports/phase2_split_assignments.csv
- configs/taxonomy.toml
- src/abstract_classifier/io/sources.py
- src/abstract_classifier/commands/train.py
- src/abstract_classifier/commands/evaluate.py
</read_first>
<action>
Create `configs/theory_baseline.toml` and the supporting dataset-loading code that reads the Phase 2 gold rows plus split assignments, validates that every supervised row resolves to one canonical taxonomy label, and exposes deterministic `train`, `val`, and `test` partitions keyed by `record_id`. The loader should also be able to pull governed source metadata for future text-variant assembly without mutating raw files or rebuilding Phase 2 artifacts.
</action>
<acceptance_criteria>
- `configs/theory_baseline.toml` exists and names the Phase 2 gold artifact, split artifact, taxonomy config, and default text variant
- dataset-loading code rejects missing `record_id` or split mismatches
- dataset-loading code exposes `train`, `val`, and `test` partitions from `phase2_v1` without reshuffling the split
- `.\.venv\Scripts\python.exe -m pytest tests/test_theory_baseline_config.py tests/test_theory_dataset_loader.py -q` exits 0
</acceptance_criteria>
</task>

<task id="03-01-02">
<title>Implement the supervised train flow and persisted run manifest</title>
<read_first>
- configs/theory_baseline.toml
- .planning/phases/03-baseline-theory-classifier/03-CONTEXT.md
- .planning/phases/03-baseline-theory-classifier/03-RESEARCH.md
- src/abstract_classifier/commands/train.py
</read_first>
<action>
Replace the placeholder `train` handler with a governed baseline training path that fits one supervised model using only the train split and persists a run directory under `reports/`. The run directory must include a manifest describing the input artifacts, split version, model family, text variant, and artifact locations, along with the serialized model and any label-mapping or coverage-support files needed by `evaluate`.
</action>
<acceptance_criteria>
- `src/abstract_classifier/commands/train.py` no longer imports or uses the placeholder handler
- the train workflow fits only on the governed train split
- a per-run directory is created under `reports/` with a manifest and model artifact
- the run manifest records `run_id`, input artifact paths, split version, taxonomy config path, and text variant
- `.\.venv\Scripts\python.exe -m abstract_classifier.cli train --config configs/theory_baseline.toml --run-id smoke_train --output-dir reports/tmp_phase3/train_smoke` exits 0
</acceptance_criteria>
</task>

<task id="03-01-03">
<title>Implement the evaluation bundle and regression tests</title>
<read_first>
- configs/theory_baseline.toml
- src/abstract_classifier/evaluation.py
- src/abstract_classifier/commands/evaluate.py
- .planning/phases/03-baseline-theory-classifier/03-VALIDATION.md

- `tests/test_theory_train_artifacts.py` and `tests/test_theory_evaluate_metrics_bundle.py` exist
- `.\.venv\Scripts\python.exe -m pytest tests/test_theory_train_artifacts.py tests/test_theory_evaluate_metrics_bundle.py -q` exits 0

</task>
