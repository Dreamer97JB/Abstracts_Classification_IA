# Plan 03-02: Benchmark agreed input variants and persist comparable experiment outputs

## Objective

Make the agreed text-input comparison reproducible by benchmarking `abstract_only` versus `abstract_plus_keywords` on the frozen Phase 2 split and persisting directly comparable outputs with honest keyword-coverage reporting.

<must_haves>
- Text variants are selected from config or CLI flags, not notebook edits.
- `abstract_plus_keywords` stays governed and records missing-keyword coverage honestly.
- Comparison outputs make the two agreed variants directly comparable on the same split and metrics schema.
</must_haves>

<tasks>
<task id="03-02-01">
<title>Implement governed text-variant assembly and coverage reporting</title>
<read_first>
- .planning/phases/03-baseline-theory-classifier/03-CONTEXT.md
- .planning/phases/03-baseline-theory-classifier/03-RESEARCH.md
- reports/phase2_gold_supervision.csv
- src/abstract_classifier/io/sources.py
- src/abstract_classifier/contracts/sources.py
</read_first>
<action>
Add text-assembly helpers that build `abstract_only` and `abstract_plus_keywords` representations from governed artifacts keyed by `record_id`. The keyword-enriched variant must append available `author_keywords` and `index_keywords`, fall back cleanly when keywords are absent, and emit coverage statistics that show how much enrichment was actually available by source and split.
</action>
<acceptance_criteria>
- the text-variant helper supports the exact variant names `abstract_only` and `abstract_plus_keywords`
- rows with missing keywords still produce valid model input text
- a coverage-summary artifact or manifest section reports keyword availability for the run
- `.\.venv\Scripts\python.exe -m pytest tests/test_theory_text_variants.py -q` exits 0
</acceptance_criteria>
</task>
