# Plan 02-02: Reviewed theory candidate tables, gold filtering, and split leakage controls

## Objective

Turn the config-driven theory mapping surface into governed candidate and gold-table artifacts with reproducible split metadata and explicit same-article leakage controls.

<must_haves>
- One canonical candidate supervised table exists for `Seed` and `Muestras`.
- Gold inclusion is explicit and testable through `include_in_gold`.
- Same-article groups never leak across train/validation/test outputs.
</must_haves>

<tasks>
<task id="02-02-01">
<title>Build the canonical candidate supervised table and gold inclusion filter</title>
<read_first>
- .planning/phases/02-label-harmonization-and-reviewed-gold-set-assembly/02-CONTEXT.md
- .planning/phases/02-label-harmonization-and-reviewed-gold-set-assembly/02-RESEARCH.md
- configs/supervision.toml
- src/abstract_classifier/supervision.py
- src/abstract_classifier/io/sources.py
- docs/alcance_cliente/gold_set_v1_spec.md
</read_first>
<action>
Extend `src/abstract_classifier/supervision.py` so it can write a canonical candidate supervised table across `Seed` and `Muestras` with the exact columns `record_id`, `source_dataset`, `source_sheet`, `title`, `abstract`, `year`, `doi`, `label_original`, `label_canonica`, `canonical_id`, `mapping_status`, `mapping_notes`, `review_required`, `include_in_gold`, `title_normalized`, `doi_normalized`, and `abstract_hash`. Compute `include_in_gold = false` for blank labels, `No`, `revision_manual`, `sin_etiqueta`, missing or too-thin abstracts, and unresolved duplicate-conflict rows. Keep the candidate table lineage-complete even when a row is excluded from gold.
</action>
<acceptance_criteria>
- The candidate supervised output includes the exact columns `record_id`, `source_dataset`, `source_sheet`, `title`, `abstract`, `year`, `doi`, `label_original`, `label_canonica`, `canonical_id`, `mapping_status`, `mapping_notes`, `review_required`, `include_in_gold`, `title_normalized`, `doi_normalized`, and `abstract_hash`
- Rows with `mapping_status = revision_manual` have `include_in_gold = false`
- Rows with `mapping_status = sin_etiqueta` have `include_in_gold = false`
- `abstract_hash` is populated for rows with non-empty abstracts
</acceptance_criteria>
</task>

<task id="02-02-02">
<title>Implement same-article grouping, duplicate handling, and reproducible split artifacts</title>
<read_first>
- src/abstract_classifier/overlap.py
- src/abstract_classifier/supervision.py
- docs/alcance_cliente/gold_set_v1_spec.md
- .planning/phases/02-label-harmonization-and-reviewed-gold-set-assembly/02-CONTEXT.md
- .planning/phases/02-label-harmonization-and-reviewed-gold-set-assembly/02-VALIDATION.md
</read_first>
<action>
Create `src/abstract_classifier/splits.py` that consumes the canonical candidate table, groups same-article rows using exact `doi_normalized` or exact `title_normalized + year`, records the grouping key in the split artifact, and assigns only gold-eligible rows to `train`, `val`, or `test` with a fixed stored seed and split version. Ensure grouped duplicates stay in the same partition and keep explicit review/exclusion rows out of the split output unless they are written to a separate excluded-rows artifact.
</action>
<acceptance_criteria>
- `src/abstract_classifier/splits.py` exists
- The split artifact contains `record_id`, `split`, `split_version`, `split_seed`, and a same-article grouping key
- The grouping logic references exact `doi_normalized` or exact `title_normalized + year`
- Tests prove that same-article groups do not land in different split buckets
</acceptance_criteria>
</task>
